# P7 橋脚の JRSNAP 静的非線形解析を FrameWeb で再現する

ニュージャパンコンサルタンツ「26_LRT鉄道照査」の P7 橋脚（WebPier で作った直接基礎の RC 橋脚）について、JRSNAP 5.2-L03 で行われた静的非線形解析（0711 線路方向・0721 線路直角方向、それぞれ Case1〜4）を FrameWeb で解き直し、結果を段階ごとに比べた記録です（2026-10-31、FEMPython 1a39aa1 に本作業の変更を加えたもの）。

## 結論

- **8 ケースとも、FrameWeb は JRSNAP と同じ解析を最後まで解きました。** 基部のせん断力、基礎のモーメント・回転角、M-θ 要素のモーメント、柱上端の変位の差は、どのケースも最大 0.6% 以下で、±1% に入りました。
- **M-θ 要素が降伏点（骨格の2点目）を過ぎる段階は、FrameWeb が 0〜2 段階遅いだけです。** 第1折れ点・第3折れ点と、基礎の回転ばねが第2勾配に入る段階は同じです。
- **M-θ 要素の回転角は、線路方向の Case1・Case2 だけが 1% を超えました（1.43%・5.21%）。** 降伏点のすぐ後で、JRSNAP の回転角が JRSNAP 自身の骨格から外れているためです（最大値の 5.6%・18.2%）。FrameWeb の状態は骨格の上にあります（差を調べたこと）。
- この再現のために、FrameWeb に次の3つを足しました。
  - 固定荷重・増分荷重・限定増分荷重（`load` の基本ケースの `kind`・`limit`）と、非線形解析の組合せ（`nonlinear_combine`）。
  - 非線形の梁（`nonlinear_bar`）に載せる部材の分布荷重。
  - 変位制御で、短く硬い要素があっても連立方程式の解を受け入れる判定（後退誤差）。

| 制御 | 変位増分。線路方向は節点2の X を −0.300 m まで 300 段階、線路直角方向は節点1を +0.350 m まで 350 段階 |
| 荷重 | 基本ケース7つ。1〜4（死荷重・付加死荷重・浮力・地震時の活荷重）は固定荷重、5（上部工の慣性力）と7（自重の慣性力）は増分荷重、6（活荷重の慣性力）は限定増分荷重。MDV 2000、LiMiT3 100、JALF 2 |
| 結果 | 8 ケースとも目標の段階まで解析し、`解析実行Err.log` は空 |

| 線形の要素 | E 2.5e7 kN/m²、A 1000 m²、I 1000 m⁴（剛域）。せん断変形なし | .ndt の MEMBER |

| 制御 | 変位制御。目標は JRSNAP と同じ（固定荷重の状態からの増分） | |
| 収束 | 判定値 1e-6（FrameWeb の既定）、反復 200 回まで | 1e-8 では丸めの限界より下になり、線路方向 Case2 の段階 268 で止まった |

### 荷重

- JRSNAP の増分の指示 0・1・4 を、基本ケースの `kind` の `fixed`・`incremental`・`limited` にしました。1つの基本ケースの中で指示は揃っています（違えばスクリプトが止まる）。
- **λ は JRSNAP の lo_step_no/MDV×JALF（＝lo/1000）と同じもの**です。増分荷重は λ＝1 で入力値になります。
- **限定増分荷重は、λ＝LiMiT3/MDV×JALF＝0.1 で入力値の全量になり、そこで止まります**（倍率 min(λ/0.1, 1)。JRSNAP では段階 1 の節点1の釣り合い 800λ＋90μ＝35.7 kN で、λ＝0.021 のとき μ＝0.21）。FrameWeb も同じ式なので、`limit` を 0.1、組合せの係数を 1 にしました。
- 節点荷重は H・N・M をそのまま `tx`・`ty`・`rz` にしました。
- 要素荷重は、iT 4（軸方向の分布荷重、柱の自重）を全体の y（下向き）、iT 1（要素に直角な分布荷重、自重の慣性力）を全体の −x にしました。柱（上が i 端）だけに載っているので、スクリプトはそれ以外を受け付けません。iT 1 の向きは、増分荷重の合計 10325.0 kN（線路方向）が JRSNAP の釣り合いと合うことで確かめました。
- **M-θ 要素に載った荷重は外しました。** JRSNAP はこの要素の荷重を解析に入れていません（段階 0 の鉛直反力 21644.846 kN は、要素 6 の 6.86 kN を除いた合計と一致）。

### 回転ばね

- K1＝kv·B³·L/12 は、段階 0 の回転角とモーメントの比と一致します（線路方向 2.6295e7、直角方向 7.3041e7 kN·m/rad）。
- M1＝N·B/6 の N は、固定荷重の鉛直の合計です（21644.846 kN）。
- Mmd を求める式は分かっていません。そこで DB1 から測りました。第3勾配では M−K3·θ が一定なので、回転角が戻り始めるまでの全段階の平均から Mmd を出しています。
  - 線路方向：Case1 は 59767.96 kN·m、Case2 は 59769.45 kN·m（どちらもばらつき 13〜36 kN·m）
  - 直角方向：Case1 は 99133.77 kN·m、Case2 は 99127.29 kN·m（ばらつき 1e-6）
  - ρm で 0.01% 未満ながら値が変わるので、αf＝1 の Case はそれぞれ自分の値を使いました。
- **αf＝2 の Case3・4 は、JRSNAP の結果が Mmd に届いていません。** 仮に「ρm が同じ αf＝1 の Case の Mmd × αf」とし、JRSNAP が達した最大のモーメントより大きいことをスクリプトで確かめています。この Case の第3勾配の動きは確かめていません。
- 除荷（柱が軟化して基礎の回転が戻る区間）は、どちらも K1 の勾配で戻ります。JRSNAP の支点の反力の欄（jiban_hanryoku）は除荷の間も骨格の値を出し続けるので、基礎のモーメントは基礎の節点に入る要素の Mj と比べました。

### 差を調べたこと

- **せん断力の 0.1〜0.2%**：JRSNAP の変位増分は、荷重を整数の段階（lo/MDV）で増やし、足りない分の力を制御節点に足して変位を合わせます。足す力は最大でせん断力の 0.17%（線路方向）・0.39%（直角方向）でした。FrameWeb は荷重のパターンのまま倍率を連続に動かすので、この分だけ荷重の分布が違います。最初の段階はせん断力が小さいので差が目立ちます（線路方向 Case1 の段階 1 で 247.4 kN と 246.4 kN）。
- **M-θ 要素の回転角（線路方向 Case1・Case2）**：降伏点から先の骨格（2点目〜3点目）の勾配は、第1勾配の約 1/5000 です。このため、モーメントのわずかな差が、回転角の大きな差になります。
  - FrameWeb の状態は、全段階で骨格の上にあります（ずれ 1e-14 以下）。
  - JRSNAP は、自分のモーメントを骨格に当てた回転角から外れています。線路方向 Case2 の段階 294 では、モーメント 64159.3 kN·m がまだ M2（64209.6）に届いていないのに、回転角 2.2601e-3 は θ2（2.1629e-3）を超えています。
  - FrameWeb との差は、どの Case でも JRSNAP 自身のずれより小さくなっています。
  - JRSNAP の .LOG の「剛性低下未収斂」は、基礎が第2勾配に入るころ（荷重の段階 389〜466）にしかありません。降伏点の近くで外れる理由は、収束を剛性低下率（FTM 0.001）で判定しているためと推定していますが、確かめていません。
- **M-θ 要素の長さ**：JRSNAP の M-θ 要素は、両端の節点の水平変位が同じです（段階 0 で差 6e-18 m）。長さのない回転ばねとして動いています。FrameWeb は長さ 0.010 m の梁なので、回転角×0.010 m だけ上の節点が余分に動きます。上端の変位で 0.02% 以下です。
- **モーメントを見る位置**：FrameWeb は要素の中央でモーメントを見ます。0.010 m の要素では、端との差は V×0.005（最大約 50 kN·m、0.09%）です。

## FrameWeb に足したもの

- **固定荷重・増分荷重・限定増分荷重**：`load` の基本ケースに `kind`（`fixed`・`incremental`・`limited`）と、限定増分のときは `limit` を書きます。どの段階でも「固定荷重 ＋ 増分荷重 × λ ＋ 限定増分荷重 × min(λ/limit, 1)」を載せます（限定増分荷重は λ＝limit で入力値の全量になり、そこで止まる）。`kind` は `nonlinear_combine` で使うときだけ意味を持ちます（ないところに書くとエラー）。
- **`nonlinear_combine`**：`combine` と同じ形の表です。1行が1回の静的非線形解析で、`C<基本ケース番号>` に係数を書き、解析の設定（`displacement_control`・`load_factors`・`n_load_steps`・`max_iterations`・`tolerance`）もその行に書きます。結果は行ごとに1つのケースになります。
- **変位制御と固定荷重**：固定荷重があるときは、最初の段階で固定荷重だけを載せ（λ＝0）、制御の目標はその状態からの変位とします。
- **非線形の梁の分布荷重**：線形の梁と同じ整合荷重を節点に載せ、部材端の力からその固定端力を差し引きます。
- **連立方程式の判定**：変位制御の方程式の解は、残差を |K||Δu|＋|R| と比べる判定（後退誤差）で受け入れます。

試験は `FrameWeb/tests/integration/test_load_kinds.py`（荷重の区別と組合せ）、`FrameWeb/tests/solvers/test_unification.py`（判定）、`FrameWeb/tests/integration/test_jrsnap_p7.py`（この検証の8ケース）です。

## 気をつけること

- デスクトップ（FrameWebforCS）で開いて保存し直すと、`kind`・`limit`・`nonlinear_combine` は消えます。保存のときに、荷重ケースを決まった項目だけから組み立て直すためです。
- runner（FrameWebforCS.Headless）は非線形解析の設定を Python に渡さないので、このモデルは runner では解けません。Python の FrameWeb で直接解きます（`scripts/compare.py`）。

## 作り直し方

リポジトリの直下（FEMPython）の PowerShell で行います。DB1 の取り出しには 32 ビットの PowerShell と SNAPDBLib（Aggre-SE のビルド）が要り、DB1 と同じ名前の結果ファイルをすべて同じフォルダに置く必要があります。

```powershell
# 1. DB1 を取り出す（Case ごと。<作業フォルダ> は DB1 とその仲間のファイルを写した場所）
& "$env:SystemRoot\SysWOW64\WindowsPowerShell\v1.0\powershell.exe" -NoProfile -File FrameWeb\tools\jrsnap_golden\extract_db1.ps1 -Db1 <作業フォルダ>\L1.DB1 -OutJson <作業フォルダ>\L1.json

# 2. 比べる値にする（Case ごと）
uv run --project FrameWeb --locked python "FrameWebforCS\tests\data\JRSNAP検証\scripts\make_reference.py" <作業フォルダ>\L1.json "FrameWebforCS\tests\data\JRSNAP検証\reference\線路方向_Case1.json" "FrameWebforCS\tests\data\JRSNAP検証\jrsnap\線路方向_Case1.ndt"

# 3. FrameWeb の入力を作り、解いて比べる
uv run --project FrameWeb --locked python "FrameWebforCS\tests\data\JRSNAP検証\scripts\make_models.py"
uv run --project FrameWeb --locked python "FrameWebforCS\tests\data\JRSNAP検証\scripts\compare.py"

# 試験
uv --directory FrameWeb run --locked --extra dev python -m pytest tests/integration/test_jrsnap_p7.py -q
```
