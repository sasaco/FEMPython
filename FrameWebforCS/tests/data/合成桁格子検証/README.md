# 合成桁の設計例で橋面荷重を検証する

`../合成桁の設計例と解説.pdf` の 36〜40 頁（本文の頁番号 24〜28。5.1 設計方針〜5.4.1 断面力）に示された格子解析を、FEMPython の橋面荷重（`bridge_loads`）で解き直し、結果を比べた記録です（2026-10-30、engineVersion 1.0.0+da2d03d）。

## 結論

- **荷重の配分は設計例と一致しました。** 橋面荷重の合計は全ケースで手計算と同じです（合成前 2824.2 kN、合成後 522.2 kN）。G1 の結果から逆算した合成後の線荷重 7.214 kN/m は、てこの原理の 7.218 kN/m とも、設計例の値から同じ方法で逆算した 7.22 kN/m とも合います。
- **断面力はおおむね ±1% で合いました。** ずれが大きいのは合成後死荷重の曲げモーメント Mvd で、G1 は小さく G2 は大きく、±3〜5% です。原因は荷重ではなく格子の剛性の仮定です（後述）。
- **FEMPython の側で直すべき問題が見つかりました。** 橋面荷重の準備が三角形の数の2乗で遅く、細かいモデルは runner の 10 分の上限を超えます（後述）。

### 設計例の値から分かること

- **Mv は合成後死荷重を含みます。** Mv＝Mvd＋ML です（例：G1 中央 3981＝500＋3481、本文 39 頁の ML）。
- **床版の荷重は、てこの原理で主桁に配っています。** 主桁の間は単純梁、張出しは G1–G2 の単純梁の張出しとして配ります。
  - 合成前死荷重の合計 85.57 kN/m と合成後死荷重の合計 15.825 kN/m は、Ms・Mvd の総和から逆算した値と一致します。
  - G1 の合成後の線荷重は、てこの原理で 7.218 kN/m です。設計例の Mvd（J1 542、中央 500）から「線荷重＋中央の集中力」として逆算した 7.22 kN/m と合います。
  - このとき中央で横桁が運ぶ力は合成前 −7.4 kN、合成後 58.6 kN です。合計 51.2 kN は、横桁の死荷重せん断力（本文 108 頁）と一致します。
- **横分配影響線（本文 100 頁）は、主桁の間で直線です。** 主桁の位置の値は G1 0.731、G2 0.367、G3 0.072、G4 −0.170 です。

### 張出しの荷重をてこの原理で配る方法

橋面荷重は、構造の節点が囲む範囲の外へ荷重を載せられません（外挿は拒否）。張出しの荷重を設計例と同じ「G1–G2 の単純梁の張出し」として配るため、次の部材を足しました。

- 床版の端（y＝−1.025、8.675）の各断面に節点を置き、片持ちの部材（要素 7）で G1・G4 に剛結する。
- G1→G2・G4→G3 に伝達の部材（要素 6）を置き、G2・G3 側の端の回転をすべて解放する。

主桁のねじり剛性がほぼ 0 なので、G1 の回転を止めているのはこの伝達の部材だけです。そのため張出しの荷重による偶力は、G1 に＋Pe/s、G2 に −Pe/s として伝わります。G1 と G2 のたわみの差では力は生じず、伝達の部材は格子の剛性を足しません。

### 荷重（すべて橋面荷重。普通の部材荷重は使わない）

- **パネル**：床版の全幅（6 本の線 × 断面）を三角形で覆うパネルを1つ作る。
- **面荷重**：橋軸方向の2本の経路のあいだに載せる。
- **線荷重**：1本の経路に載せる。ハンチ・鋼重は主桁の線の上に置く。

| ケース | 内容 | 断面 |
|---|---|---|
| 1 | 合成前死荷重 Db | 鋼桁 |
| 2 | 合成後死荷重 Da | 合成 |
| 3〜6 | 横分配の確認：支間中央の G1〜G4 に 100 kN の節点荷重 | 合成 |
| 7〜12 | 活荷重（`scripts/live.json`） | 合成 |

活荷重は、最も不利な位置を自動では探せないので、位置を次のように決めて載せました。設計例に載荷位置は書かれていないため、これは仮定です。

- **強度**：p2（3.5×1.241 kN/m²）は全支間に載せる。p1（曲げは 10、せん断は 12 kN/m²、×1.241）は長さ 10 m。
- **幅**：主載荷 5.5 m は地覆の内側の左端（y＝−0.425）から全強度。その外は 1/2 の強度を、影響値が正の範囲だけに載せる。G1 は y＝5.844（G1 の横分配が 0 になる位置）まで、G2 は y＝8.075 まで。G2 の反力だけは主載荷を y＝−0.2〜5.3 とした。
- **p1 の橋軸方向の位置**：支間中央の曲げは x＝11.5〜21.5、J1 の曲げは x＝7.144〜17.144（両端の影響値が等しくなる位置）、反力は x＝0〜10。

- 2.75 m 間隔（runner で計算）との差は 1% 未満でした（`results/summary_2.75m_*_runner.json`）。

## 見つかった問題

1. **橋面荷重の準備が、三角形の数の2乗で遅い**（`FrameWeb/src/fem/spatial_loads/validation.py` の `prepare_geometry`）
   - 載荷メッシュ（`loading_nodes`）が無いとき、`prepare_panel` は `domain_cells = cells` とします。そのため `for cell in panel.cells: for domain in panel.domain_cells or panel.cells:` が、面荷重の帯ごとにセルを総当たりで切り抜きます。
   - 三角形 140 個の面荷重2つで `clip_polygon` が 78,400 回呼ばれ、1 ケース 10 秒かかりました。
   - runner の時間：三角形 140 個（2.75 m 間隔）・12 ケースで 25 秒。360 個（1.0 m 間隔）では 10 分の上限を超えて `CANCELED`（`results/runner_1.0m_canceled.json`）。1,320 個（0.25 m 間隔）も同じでした。
   - 検証では `scripts/drive.py patch` で「載荷メッシュが無いときは当のセルだけで切る」に差し替えました（リポジトリは変えていません）。粗いモデルで差し替えの前後を比べ、反力・変位の差は 0、速さは 5 倍でした。
   - 0.25 m 間隔の値はこの方法で FemModel を直接動かして出しました。それでも面荷重のケースは 1 ケース 60〜85 秒かかります（`results/time_0.25m_*.log`）。ほかにも遅い所が残っています。
2. **張出しには作り込みが要る**：橋面荷重は構造の外へ載せられないので、上の「張出しの荷重をてこの原理で配る方法」が必要でした。
3. **3D の runner は PIK を止める必要がある**：`--generate-pik false` が要ります（既定のままだと `PIK_REQUIRES_2D`）。

## 作り直し方

リポジトリの直下（`FEMPython`）で、PowerShell から実行します。

```powershell
$d = "FrameWebforCS/tests/data/合成桁格子検証"
# runner（2.75 m 間隔）
$env:SHEAR = "none"; $env:DX = "2.75"; $env:LIVE_SPEC = Get-Content "$d/scripts/live.json" -Raw
node "$d/scripts/gen.mjs" "$d/models/model_2.75m_none.json"
New-Item -ItemType Directory C:\tmp\grid-run
& FrameWebforCS/Headless/bin/Release/net10.0-windows/FrameWebforCS.Headless.exe run `
  --input (Resolve-Path "$d/models/model_2.75m_none.json") --output-dir C:\tmp\grid-run `
  --generate-pik false --generate-pdf false
node "$d/scripts/read.mjs" C:\tmp\grid-run\result.json "$d/models/model_2.75m_none.map.json"

# FemModel を直接（0.25 m 間隔、差し替えあり）
New-Item -ItemType Directory C:\tmp\grid-fine
$cases = foreach ($c in 1..12) {
  node "$d/scripts/onecase.mjs" "$d/models/model_0.25m_none.json" $c "C:\tmp\grid-fine\m_case$c.json"
  "C:\tmp\grid-fine\m_case$c.json"
}
uv run --project FrameWeb --locked python "$d/scripts/drive.py" C:\tmp\grid-fine\result.json patch @cases
node "$d/scripts/read.mjs" C:\tmp\grid-fine\result.json "$d/models/model_0.25m_none.map.json"
```
