# Quality review: desktop direct PDF printing

## Scope

Reviewed the approved plan, legacy parity inventory and scoped patch, then traced the changed desktop projection, modal preview/save/print path, viewport capture/state restoration, and direct PDF library against the reachable Angular print controls and `PrintInput` contract. The unrelated partial-member-spring plan was excluded.

## Findings

### [High] The reachable 2D displacement diagram output is dropped

- **File:** `FrameWebforCS/providers/printing/PrintProjection.cs:591-609`
- **Evidence:** `PrintDialogForm` offers `disg` under result diagram components. The legacy single-diagram path appends `disg` to `diagramResult.output` when selected (`FrameWebforJS/src/app/components/print/print.component.ts:926-934`). `AddVectorDiagrams` limits the base `PrintDiagram` output to `fx`, `fy`, `mz`. Selecting only `disg` throws a no-components exception; selecting it with force components silently omits the displacement diagram. The root `disg` and `disgName` prepared at lines 301-303 and 617-620 do not make it printable without the output flag.
- **Fix:** Include `disg` in the base `PrintDiagram` output choices, preserve the legacy order, and add focused tests for `disg` alone and with force components. Keep derived diagram choices aligned with what the legacy parser supports.

### [Medium] An available result family can fail with the default all-cases filter

- **File:** `FrameWebforCS/providers/printing/PrintProjection.cs:95-104,289-294,321-380`
- **Evidence:** `GetAvailability` enables reaction or section-force printing when *any* page has rows. The modal presents an empty case selection as all cases. `AddBaseFamily` then walks *every* result page and throws if a modal page or a page without that family's rows is present. A mixed static/modal result set, or cases with different support sets, can therefore offer an enabled print item whose default operation fails despite printable cases. One shared case filter also makes simultaneous displacement and reaction output across mixed page families impossible without excluding otherwise printable displacement pages.
- **Fix:** Derive eligible pages per selected family and let the UI show/filter them coherently; keep explicit invalid selections actionable. Add a mixed-family fixture for the default and combined-option paths.

## Verified behavior and limits

- The print menu opens an owner-bound `ShowDialog`; projection detaches mutable input; preview, save, and print use the same generated bytes. The viewport capture uses an off-screen target and restores prior state in a `finally` block.
- The screenshot's `Assert.False()` dialog came from the earlier shared-desktop xUnit STA test, according to the lead and UI implementer. It was fixed and is not a product finding.
- No independent rendered-page parity or physical/virtual printer run was performed in this review. The integration lead owns those gates.

## Remediation verification

- **High finding resolved in projection:** `PrintProjection.cs:618-649` now includes `disg` in the base 2D `PrintDiagram` output in legacy order (`mz`, `fy`, `fx`, `disg`) and attaches `disg`/`disgName` when selected. `PrintProjectionTests.cs:213-232` checks `disg` alone, with `fx`, and with all three force outputs. The legacy PDF `DiagramResult` parser accepts `disg` in `output` and reads the attached displacement data.
- **Medium finding resolved in projection:** `PrintProjection.cs:282-303,345-346,409-410` selects eligible pages per result family and rejects a family only when the selected cases provide no rows. `PrintProjectionTests.cs:234-258` covers the mixed static/modal default, simultaneous result families, explicit mixed cases, and an ineligible modal-only reaction selection. The 3D request path also filters base cases by family eligibility at `PrintProjection.cs:672-679`.
- The integrating team reports 21/21 focused projection tests and a passing product build. This read-only follow-up did not rerun those gates or perform rendered-page/printer acceptance. No residual bug was found in the two reviewed remediations.
